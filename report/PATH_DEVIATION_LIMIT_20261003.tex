\section{Requirement and implemented constraint}
The user's maximum deviation refers to the ego center's absolute lateral
projection onto the given path. The new default
\path{controller.maximumLateralDeviationMeters=10} adds a hard finite-prediction
constraint. It is separate from the displayed road width, the 0.10-m affine
collision margin and the single unchanged CLF. No lateral penalty, new control
mode, actuator limit, executable backup or additional trajectory-linearization
loop is introduced. Setting the limit to infinity explicitly disables it.

The two affine lateral half-planes are exact on a straight path. For a circular
path with center $c$ and radius $R$, an anchor radial unit vector $n$ gives
\[
 n^\top(p-c)\ge\max(0,R-L),\qquad \|p-c\|_2\le R+L.
\]
The inner half-plane is sufficient for the annulus exterior; the outer disk is
exact. Both optimization stages enforce these constraints at hold starts,
model midpoints and the endpoint, including the completion tail. PCBF slack
cannot relax them. Future nodes reserve 0.01 m from the 10-m limit, using the
existing position-agreement tolerance; the fixed initial state uses 10 m.
The initial-state constraint therefore rejects an already out-of-bound state.

The existing nonlinear rollout independently measures the full trajectory's
maximum nodal deviation, and its agreement ratio cannot pass with deviation
above $L$. Existing damping and failed-shift reinitialization remain the only
correction mechanisms. This does not add a nonlinear rollout or a solver stage.
Primary zero-point detection and inherited-anchor residuals now account for
all primary cones, rather than only the endpoint cone.

Rows already implied by the correction box are removed. For $p=\bar p+Mz$,
$|z|\le b$ implies $|Mz|\le |M|b$. Thus a disk whose bound exceeds
$\|\,|\bar p-c|+|M|b\,\|_2$ is redundant. The box includes the existing maximum
input expansion, so later expansion cannot invalidate this elimination.

\section{Why initialization also needed adjustment}
The old 15-m/s curved-head-on cold seed ended at 18.598 m lateral offset,
although its executed closed loop peaked at 11.145 m. A 10-m hard tail bound
cannot be repaired inside the existing 2.5-m state correction box there.
Simply adding the bound made the first convex problem infeasible.

The potential-field lateral guidance velocity is now projected onto
$(-L-e_y)/T\le v_{y,\mathrm{guide}}\le(L-e_y)/T$, with the existing 1.5-s guidance
lookahead $T$. This is a seed-shaping condition, not a bicycle safety proof.
The final configuration uses four seconds of completion, with the last 1.5 s
for intrinsic terminal settling, allowing a longer guided return before the
terminal straight segment. Startup input trust scale is 0.125; normal frames
still inherit their accepted scale. The 8/16-step prefix and 50-ms hold remain.
These are declared development adjustments on the same scenario family,
not independent holdout validation or an isolated effect of the bound alone.

A shorter 1-s settling trial with the original 3-s completion recovered in
10/14 cases: two low-speed cold starts, one high-speed curved cold start and
the later curved-head-on encounter failed model agreement. Lengthening the
settling interval alone or overly restricting the guidance velocity produced
other cold-start infeasibilities. Four-second completion with 2-s settling
passed 13/14 short screens; the braking-lead seed still exceeded the corridor
and its repair failed agreement. The retained 1.5-s settling interval produced
a compatible seed. Failed trials, diagnostic captures and their source diffs
are retained separately from the final executed campaign.

\section{Complete closed-loop experiment}
Every fixture starts separated and has a collision under given-path constant
speed cruise. Target tangential acceleration and sideslip are known constants;
ego state is exact. There is no observer noise, road constraint or injected
computation delay. ODE45 uses relative/absolute tolerances $10^{-11}/10^{-12}$
and 31 audit samples per hold. Recovery uses the existing tolerances and a
one-second post-conflict dwell, including the later circular encounter. The
1,500-hold limit is an observation cap, not an eight-second success metric.

The final campaign recovered in 14/14 cases, with 0 sampled collisions, 0 deviation-limit violations and 0 solver interruptions over 4,065 issued holds. The family-wide maximum lateral offset is 7.795823 m, and the minimum sampled rectangle gap is 0.058491 m.

\section{Runtime, tests and scope}
Whole continuation-call median, 95th percentile and maximum are 23.267, 38.416 and 112.534 ms. The largest first call is 1017.096 ms. There are 1 continuation frames over 100 ms and 68 over the 50-ms hold. The unchanged one-model/fresh-restart structure uses 4015 one-model frames and 50 two-model frames, with at most 3 numerical solves in a frame.
All 410 focused MATLAB tests pass across 19 suites. New tests cover both signs
of offset, straight and circular geometry, rejection of invalid limits,
near-boundary recovery, and infeasibility of an initially out-of-bound state.
The pre-existing global CLF fixtures starting 20/40 m away explicitly disable
the new corridor. The damping fixture uses a tighter CLF-agreement tolerance
because the smaller startup correction now passes the old threshold without
damping. The initial failed assertion was a changed test trigger, not unsafe
controller behavior; the adjusted suite was rerun and combined with the other
passing suites. Source whitespace and Code Analyzer checks are recorded.

The path bound is hard in the sampled affine prediction, with a nodal nonlinear
rollout gate and dense offline replay. Neither these samples nor the inward
reserve establish continuous-plant safety or uncertainty robustness. The
existing free-pose terminal core certifies its original intrinsic-dynamics
conditions; it is not proved invariant inside the new corridor. No new
infinite-horizon or recursive path-feasibility theorem is asserted. The 0.10-m
collision setting also remains an affine-model margin, not a measured minimum
clearance guarantee. Timing is shared-workstation wall time, not a worst-case
execution deadline.
